What happens in it

  1. Set up

    Run ripcord init in a Compose project. It lists the databases and volumes and writes ripcord.yml with the app URL, login variable names and plain English checks.

  2. Prove

    Run ripcord prove. Ripcord backs up, restores a throwaway copy on a free port, and Kane logs into the live app and the copy, one run at a time.

  3. Read the verdict

    The report shows PROVEN or LOSS with each check's live and copy values side by side, the screenshots, and the row count comparison next to Kane's answer.

  4. Install the hooks

    Run ripcord hook install to add the Claude Code hooks.

  5. The agent tries something destructive

    The gate blocks the command and tells the agent to run ripcord prove first. Once a fresh PROVEN exists, the command is allowed and recorded.

  6. Verify and roll back

    After a risky command, ripcord verify has Kane reread the checks on the live app. If data is missing, ripcord rollback restores the proven backup and Kane proves the fingerprint matches again.
